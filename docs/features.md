# FluidMessages features

Everything the Android app does, in detail. For installing it, see the [README](../README.md).

## Getting started

Target device: Pixel 7 with GrapheneOS and dual SIM. The app targets Android 15 and requires Android 13 or newer. It uses the Android SMS role and does not require Google Play Services.

Open **Settings → About and updates** for the installed version, manual checks, and automatic release checks. Direct installs check GitHub about once a day while the app is open. A newer stable release can be downloaded after confirmation. The app verifies the APK’s package, signing certificate, and version code before opening Android’s installer. App store installs use their store for updates. Publish a signed APK as a GitHub Release asset named `FluidMessages-<version>.apk` on the matching `v<version>` tag, using the same signing key and an increasing version code.

Setup asks for each thing the app needs on its own page: becoming your texting app, then notifications, contacts, phone and call history, and (now or later) microphone, camera, location, and calendar. Each shows **Allowed** or **Not yet**. Android lets only one app send and receive texts, so while texting is on and FluidMessages isn't your texting app, it shows no texts and asks again each time it opens, until you make it your texting app or choose **Turn off texting in FluidMessages** (chat services keep working). The text switches in **Settings → Chat services** only turn on once it is your texting app. **SIM** in the composer selects a subscription. Long-press a conversation for pinning, archiving, or hiding it from the regular inbox. Hiding changes the local inbox and does not block carrier delivery. Text notifications show who wrote and what they said, grouped per chat, with **Reply** and **Mark as read**. Turn off **Show names and message text in notifications** to hide them; chats in the private folder and everything while app lock is on always stay generic, and a secure lock screen hides the text. A message you started but didn't send is kept as a draft for that chat. Link previews and linked pictures load by themselves only for your own messages and saved contacts; for anyone else, tap **Tap to load preview**. Open **New message** to find contacts by name, pick a recent number, or enter a new number. Select several people to use a single SMS composer. Each person receives their own text and replies in their individual chat. Android’s `smsto:` links also accept comma-separated numbers.

Setup starts with a plain sample chat and introduces chat services later. The **Communities** page shows once, the first time you add an IRC, Matrix, or XMPP account, and stays in **Settings → Help**. **Settings → Chat services** explains battery use: turning a service on costs nothing, only a signed-in account connects, and FluidMessages Web can hold those connections for the phone. Conversation details for one person have **+ Add another way to reach** under Message and Call. The phone pairs with FluidMessages Web by scanning the QR code in its pairing steps (**Settings → FluidMessages Web → Scan QR code**, a full page that asks for the camera only when tapped; it uses CameraX and ZXing, with no Google services). FluidMessages Web makes its own certificate on first start and answers phones over HTTPS on a second port (`FLUID_TLS_PORT`, 8081 by default), so no domain name is needed. The QR code carries the addresses, the link code, and the certificate's fingerprint; the phone then trusts only that certificate for FluidMessages Web, and if it ever changes, it stops and asks you to pair again. Typing still works: the address, the link code, and an optional **Certificate fingerprint**. Without a fingerprint, `https://` uses the phone's normal checks (for your own domain), and `http://` shows a warning that others on the same Wi-Fi could read the traffic. [Self-hosting](self-hosting.md) explains the HTTPS port and reaching it from outside your home.

Open the appearance editor from **Settings → Themes and appearance**, including before SMS setup. The Fluid palette uses blue for outgoing SMS and green for the automated outgoing color. Fluid and Midnight blend Apple Indigo and Purple in equal parts for the RCS preview. Incoming bubbles use system gray in light and dark mode. You can override the incoming color separately. **Color theme** lists the built-in themes and saved palettes. Individual message colors are in **Customize colors**, with Apple Indigo, Pink, Cyan and Mint featured in the RCS picker. Colored message bubbles use white text. Bright chromatic fills are shaded for contrast. Neutral bubbles choose black or white based on brightness. The swatches use the light, dark, and increased-contrast RGB values from the [Apple Human Interface Guidelines color table](https://developer.apple.com/design/human-interface-guidelines/color#Specifications). Choose a coordinated theme such as Midnight, Lavender, Evergreen, Tideline, Ember, Love, or Rosewater. Each theme has a light and dark palette. Visual color controls, custom hex, and named swatches are available. Switching themes applies the selected palette, wallpaper and default layout. **Reset to theme** reapplies the current one. Mode, sound, haptic and motion preferences remain separate. Selecting Love applies its palette and matching wallpaper. The appearance page keeps presets and the live preview at the top. Expand **Customize colors**, **Wallpaper**, **Inbox and toolbar**, **Message bubbles**, or **Motion and sound** as needed. Use **Save custom palette** to keep a named version of a preset and your color overrides. Search can sit at the top or in a bottom dock. Toolbar finish and opacity, inbox density, and bubble tails are also adjustable. Each theme has an automated outgoing color. The optional green SMS and blue RCS setup preset uses Apple system Green for SMS and Apple Purple for automated messages. In every theme, the automated color is a separate hue from that theme's SMS and RCS colors. First launch opens setup for appearance, motion, chimes, backups, privacy, and the LAN companion. Replay it or open the permission-free sample inbox from Settings. Under **Motion and sound**, set the outgoing sound and receive chime to Silent, a Fluid chime, the Android default, or a tone from the device picker. Fluid is the default: a soft swish when you send and a short three-note chime when a message arrives. Choose a haptic pattern and preview the feedback. Device tones may need reselection after restoring on another phone. The animation setting controls the sample preview, conversation entrance, and new outgoing bubble animation. App lock uses your device credential or strong biometric and hides the app from screenshots while enabled.

## Replies, reactions, and conversation appearance

Enable **Settings → Messaging → Show exact message times** for inbox date-and-time labels and a time under each bubble. Received SMS use the sender timestamp when Android supplies it. Other messages use the stored timestamp. You can always tap an individual bubble to reveal its time.

Reaction texts from iPhones and other Android apps (*Liked “…”*, *Reacted 😂 to “…”*, *Removed a heart from “…”*, *Loved an image*) become a reaction on the matching message instead of a separate text, on the phone and on the web. When nothing matches, the text stays a normal message. Your own reactions to people without FluidMessages are sent in the same standard wording. Swipe a bubble right to quote it. Long-press for a reaction strip, Reply, Forward, Copy, Select text, Share, Message details, and Delete for me. Forward opens an editable draft for the recipient you choose. It sends readable SMS such as `Forwarded “Coffee at ten?” by “Maya Chen”`; FluidMessages renders that text as a forwarded card. Replies send the quote and reply body as readable SMS. FluidMessages shows compatible reply text as a quote card, and tapping a matched quote jumps to the original message. A thumbs-up sends text such as `Liked “Coffee at ten?”`. The **+** in the reaction strip accepts an emoji from your keyboard or clipboard. FluidMessages folds compatible standard and custom emoji reactions onto the matching earlier message. Unmatched reactions remain visible as text. React to incoming messages or your own outgoing messages. Each person keeps one reaction per message: choosing your current reaction again removes it and sends `Removed a like from “Coffee at ten?”`, the wording iPhones use, and choosing a different one sends `Changed reaction from 👍 to ❤️ on “Coffee at ten?”`, so people on other apps know what changed. FluidMessages folds both, in one-to-one and group chats, on the phone and in the browser companion. Matrix and XMPP remove and change reactions natively: Matrix redacts your earlier reaction event, and XMPP sends your updated reaction set (XEP-0444). When someone else takes back a Matrix or XMPP reaction, it disappears from the bubble too. SMS, MMS, IRC, and email send the readable text, since IRC has no way to take a reaction back and RFC 9078 doesn't define one for email. Update the companion as well, so it sends removals natively instead of treating them as new reactions. A reaction to your own message adds `(my message)` to the SMS so FluidMessages can distinguish the two cases. Matching uses the quote and sender, so repeated identical texts may match the latest one. Every protocol sends through the same message layer, so reply, react, and forward work the same way in each chat. Matrix replies and reactions use native `m.in_reply_to` and `m.annotation` events, and Matrix reactions from other clients fold onto the matching message. Incoming email replies drop the quoted earlier conversation (the “On … wrote:” line, Outlook’s header block, and trailing `>` lines), since the bubble already shows when it was sent. When someone answers an older email than the latest one, a reply card shows which. Emails received before this are cleaned once on the phone and the companion. Email replies thread onto the exact message with `In-Reply-To`, and email reactions follow [RFC 9078](https://www.rfc-editor.org/rfc/rfc9078), which leaves the reaction email without the FluidMessages footer. SMS, MMS, and IRC use the readable text form above. Forwarding sends the readable forwarded text on every protocol. Use **Send as** in a sample chat to choose yourself or a fictional group member. Try the mixed **Weekend Plans**, all-RCS **Photo Walk**, and automated **Trail Crew** samples. The outgoing preview uses Automated first, then SMS, and RCS when all participants support it. Attach a photo in any sample composer. Sample photos stay local.

Tap an inbox avatar or a conversation’s name to open contact details. The inbox refreshes saved contact names and photos after edits. Search accepts partial words, accent-insensitive spelling, one-letter typos, and formatted numbers. Short codes and alphanumeric sender IDs use the automated outgoing color and conversation label. The classification follows the sender address. Incoming messages use the separate incoming color. **Edit contact** opens the Android Contacts editor. Calling, muting, pinning, and archiving are available for real SMS chats. **Theme and wallpaper** opens a live preview with built-in wallpapers, photo selection, and visual color controls. Selections save immediately for the conversation. Global wallpapers and visual colors are available in **Themes and appearance**. Selecting Love applies its palette and wallpaper together.

## Message protocols

**Settings → Message protocols** groups text messages (RCS preview, SMS, and **Allow MMS**) and internet protocols (Matrix, XMPP, Email, IRC). New messages use the first available protocol in this order: RCS, SMS or MMS, Matrix, XMPP, Email, IRC. RCS, SMS, and MMS share one conversation per person. SMS switches to MMS for photos and group chats. When RCS is offered, **via RCS ▾** above the composer, or touching and holding Send, sends a message as SMS instead. A contact with several protocols shows **via Matrix ▾** to pick how to send, and tapping the protocol under the conversation name switches which history you see. Choose **Always use … for** a contact to save a default. **Inbox protocol tags** and **Encryption status** default to **Automatic**. Tags appear once your inbox holds more than one kind of conversation, and a 🔒 line appears under the name only for end-to-end encrypted chats. Every chat's details list how it's protected. Choose Always or Off in Message protocols. **New message** accepts phone numbers and, for protocols that are on and have an account, a Matrix ID, an email or XMPP address (you choose which), an IRC #channel, or `irc:nick`. A protocol that's on but has no account offers to add one, and turned-off protocols aren't offered. An account connected from this phone pauses on the companion, so each message arrives once. With **Combine linked conversations** on, every protocol for a contact appears in one chat, and messages sent another way are labeled. Internet protocols connect automatically once the companion is paired and has accounts, and it checks every 15 minutes when it has none. A turned-off protocol stays readable, and the composer explains why it can't send. **Settings → Messaging → Privacy** removes metadata from files you send on every protocol: EXIF, XMP, and GPS from photos (by re-encoding them), container tags and location from MP4, 3GP, and WebM video and audio (by remuxing), ID3 tags from MP3, document information and XMP from PDFs ([PDFBox-Android](https://github.com/TomRoush/PdfBox-Android)), and document properties from Office and OpenDocument files. Other formats are sent unchanged.

**Settings → Battery and sync** sets how often FluidMessages checks the companion while open (10 seconds to every minute, or only when you refresh or send) and in the background (15 minutes to 6 hours, or off), whether automatic checks wait for Wi-Fi, whether they pause during Battery Saver, and when received attachments download. Carrier SMS and MMS arrive by push and are unaffected.

### Accounts and linked addresses

Adding a Matrix, XMPP, Email, or IRC account first shows a short guide: what the service is, a popular place to get an account (matrix.org, jabber.org, Libera.Chat, or the email you already have), and three steps. Typing an email address fills in the server settings for Gmail, Outlook, Yahoo, AOL, iCloud, Fastmail, Zoho, GMX, and mail.com, and links to the provider's app-password page when it needs one; a Matrix ID fills in its homeserver. IRC networks connected from the phone can browse the channel list (with a Popular here list first) and join channels by name, without FluidMessages Web. Open **Settings → Accounts** to add Matrix, XMPP, Email, or IRC accounts to your paired companion, or turn protocols on in setup and choose **Set up accounts**. Matrix asks for your password once to sign in, and the companion keeps only the session token. Passwords are stored in a private file (mode 600) in the companion's data volume and are never shown again or included in backups. Leave a password blank when editing to keep the saved one. You can also set accounts in Docker Compose with `FLUID_EMAIL_*`, `FLUID_MATRIX_*`, `FLUID_XMPP_*`, and `FLUID_IRC_*` variables (see `compose.yaml`). Those appear as **Set in Docker Compose** and are read-only on the phone. An incomplete Compose account is reported instead of stopping the companion.

Open a contact's details and choose **Link an address** to reach them by Matrix ID, XMPP address or group, email address, or IRC nick or #channel. As you type, people and addresses from your past chats on that service are suggested, searched on your device only. A Matrix ID opens your existing direct room with that person, or creates one. Only linked conversations appear in FluidMessages; other email, rooms, and direct messages stay out. Channels listed on your IRC account appear in the inbox automatically. A chat's details have real switches for Mute, Pin, and Archive; a muted chat says when it unmutes in your time zone ("Muted until Tue 3:45 PM"). One-to-one chats and contact pages have **Block** and **Unblock**, confirmed in place. Member lists longer than 10 show the first 5 with **Show all N members**.

The companion keeps one connection per account open, so your phone doesn't. **Matrix encryption:** with `matrix-nio[e2e]` (included in the Docker image), the companion becomes one of your Matrix devices. It decrypts and encrypts messages and files in encrypted rooms, and keeps its keys in the data volume, protected by a random pickle key. The phone shows those rooms as *End-to-end encrypted · decrypted on your companion*. Other people's new devices are trusted on first use, the way bots and bridges behave. To clear "unverified device" warnings for others, verify the companion's device from another Matrix client. Messages whose keys haven't arrived yet show a placeholder, and the companion requests the keys. **Connect from this phone:** in an account, choose **Connect through → This phone** instead of the companion. First accept the battery notice, which keeps **Continue** off until you turn on *I understand this uses more battery*. The phone then connects to that protocol itself: JavaMail for email, Smack for XMPP, the client-server API for Matrix, and a built-in TLS IRC client. Account details are encrypted with an Android Keystore key, stay on the phone, and are never backed up, and links you add are stored on the phone. Email and Matrix check on your Battery and sync schedule, plus a long poll for Matrix while the app is open. IRC and XMPP connect while FluidMessages is on screen. **Stay connected** keeps them connected in a foreground service with an ongoing notification, which uses the most battery. Encrypted Matrix rooms need the companion, so from the phone they show a placeholder and sending to them is declined with that reason. Without a companion, phone connections are the only option. XMPP is native (slixmpp) with stream management, message carbons, delivery receipts, group chats, replies (XEP-0461), reactions (XEP-0444), and files through HTTP File Upload. **XMPP and OMEMO.** FluidMessages Web and the phone are each one OMEMO device of your XMPP account (legacy OMEMO, `eu.siacs.conversations.axolotl`, the version Conversations, Monocles, Gajim, Dino, Siskin, and Monal speak). A one-to-one chat is locked with OMEMO when the other person's app uses it, and shows the green lock: *Locked with OMEMO: only you and the people you're talking to can read it.* When they don't use OMEMO, the message goes without it, the chat says so once, and the lock is yellow. When they have OMEMO devices but you trust none of them, nothing is sent. Group chats are locked on FluidMessages Web when the group is members-only and members can see each other's addresses; otherwise the chat says why it isn't locked. From the phone, group chats aren't locked yet. Messages to and from your other devices (carbons) and from the server's archive are opened too; one that can't be opened shows a plain notice instead. Files in locked chats are encrypted before upload (`aesgcm://` links, XEP-0454). Trust is *blind trust before verification*, like Conversations: new devices are trusted until you verify one of that person's devices, and after that new ones wait for your OK. A chat's details have **Encryption (OMEMO)**: each device of theirs and yours, its fingerprint in groups of 8 characters, and Trusted, Verified, or Off. Your own `xmpp:` link (the format Conversations shows as a QR code) can be copied, and pasting someone's link verifies their matching devices. A new device or a changed key shows a line in the chat. Reactions and message retractions aren't locked (legacy OMEMO only locks the text). OMEMO keys are encrypted on each side (on FluidMessages Web with a random key in a private file, on the phone with the Android Keystore key that protects account details) and are never in backups: after a restore, a new OMEMO device is made, as other apps do. FluidMessages Web needs the optional `omemo`, `doubleratchet`, `x3dh`, and `xeddsa` packages (MIT, in the Docker image); without them XMPP is encrypted in transit only, and the chat says so. IRC is native, TLS only, with SASL sign-in and IRCv3 replies and reactions when the server supports message tags. Unsupported features fall back to readable text. A Matrix room ID for an XMPP or IRC link still routes through a Matrix bridge. IRC conversations keep the normal bubbles, with each speaker's nickname in its own color and the time beside it. `/me` actions appear in italics, and joins, leaves, and topic changes are small outlined notes in the IRC color. The channel's details show its topic and current nicknames.

**Servers.** An IRC network such as Libera.Chat hosts many public chat rooms called channels; a Matrix homeserver and an XMPP server host rooms and group chats the same way. **Messages → Communities**, the second half of the **Chats | Communities** switch under the Messages title (on the phone and on FluidMessages Web), lists each server you've added with its avatar, name, service tag, and unread count, and under it its channels and rooms, each with its preview, time, and unread dot like any chat. Tap a server to collapse or expand it (remembered per server); its **⋯** has **Browse**, **Join**, and **Server details** (the account, and **Remove server**). The sort menu at the top orders servers and their channels by **Recent activity** (the default), **Name (A–Z)**, or **Date joined**, kept for both apps. The search box searches communities while they're showing. Channels and rooms also show in Chats like group chats; **Settings → Messaging → Show community chats in Chats** turns that off, and then Communities counts their unread messages itself instead of the Messages tab. Direct messages on those services always stay in Chats. Communities isn't shown in the sample inbox, decoy mode, or the private folder. On the phone, servers come from FluidMessages Web when it's paired, plus any IRC, Matrix, or XMPP account connected from the phone. **Add server**, at the bottom of Communities and in its empty state, is a series of full pages: choose IRC, Matrix, or XMPP, then pick from a searchable list of well-known public servers (Libera.Chat, OFTC, EFnet, IRCnet, Undernet, DALnet, Rizon, hackint, Snoonet, GIMPNet, EsperNet, and tilde.chat for IRC; matrix.org, tchncs.de, and other open homeservers; jabber.org, conversations.im, yax.im, and other XMPP services), or choose **Other server…** to enter any host. Picking one fills in the sign-in form; nothing connects until **Save**. IRC always uses TLS, so networks without it, such as QuakeNet, are listed but can't be picked. The lists live in `server/server-directory.js` and `ServerDirectory.kt`. A server's **Browse** searches its public channels or rooms as you type (IRC `LIST` with a mask, the Matrix room directory, or XMPP service discovery), with member counts and topics. **Join** adds a channel to the inbox straight away, with *No messages yet* until someone writes; joined ones show **Joined** and **Open**. **New message → Channels** lists every server's joined channels and rooms with a search field. **Remove channel** in a channel's details leaves it (or the room) and takes it out of the list, after a full-page confirm; earlier messages move to Archived, and joining again brings the chat back. Each channel has a **Rejoin automatically** switch, and each server's details have **Reconnect automatically** (on by default): turned off, the chat stays in the list but nothing connects until you tap **Reconnect**. A joined channel and each network's server chat show in Chats straight away, connected or not, and a plug beside the IRC, Matrix, or XMPP tag (next to the lock and muted marks) shows whether that connection is up (green), connecting (gray), or down (red, crossed out); a server that's turned off shows a gray crossed-out plug. A chat's details start with a **Connection** section: the status in words, **Reconnect**, **Disconnect** or **Connect**, Reconnect automatically, and Rejoin automatically for a channel. Long-press (phone) or right-click (web) a chat for **Disconnect <server>**, and the inbox filter menu's **Connections** page lists every server with a switch and Reconnect; a server you turn off stays off, also after a restart, and its chats stay in the list. In Communities, long-press or right-click a channel for **Leave and remove channel**. Channels that only let in signed-in nicknames are joined after NickServ confirms you (and retried once); when a network says to join another channel first, FluidMessages joins that one first and remembers the order (shown in the channel's details as *Also joins #lobby first*), and a channel another one needs offers to remove both. Password-locked channels ask for their password inline. The IRC account form explains **Nickname** (the name people see), **Account name** (the name you registered with NickServ, usually the same), and **Password**. When a network refuses the connection (for example Libera.Chat asking for a registered nickname from a VPN or cloud connection, or a nickname it doesn't allow), its reason is shown in plain words with what to do. In IRC chats, call, video, and meeting-link buttons are hidden by default; **Settings → Accounts → IRC** can bring them back, with a warning that many channels ban call links. When NickServ says your nickname is registered, its notices fold into one card with a password field and **Identify** (and an option to save the password to the account); **Show what NickServ said** keeps its original words.

If a message can't be sent, a red **Not delivered** notice appears under it, with the reason when one is known. Tap it to try again, edit and resend, or delete.

### Nearby: messaging with no internet

**Settings → Chat services → Nearby** lets you message FluidMessages friends close by with no internet or cell signal, over Bluetooth or the same Wi-Fi. It's off until you turn it on and pick the name people see; Bluetooth access is asked for only then, and saying no leaves Wi-Fi working. **What works in a blackout:** messages between FluidMessages phones with Nearby on that are within Bluetooth range (about one room to a few houses) or on one Wi-Fi network (a router on battery, or one phone's hotspot, works even when that network has no internet). Phones carry messages for each other as people move around, so a message can reach someone out of range later. **What doesn't:** nothing reaches phones without FluidMessages, nothing goes beyond the people around, and there are no calls or photos yet. No internet, cell signal, server, or carrier is involved.

- **Adding someone, in person.** Each of you adds the other, in any of these ways, and none needs a camera: **Show my code** (a QR code, also shareable as text with **Share my code as text**), **Scan their code** (take a photo of it or choose a picture of it), **Type their code**, or **Add nearby person**, where both phones on that page find each other on the Wi-Fi and show the same six-digit safety code. Check that both codes match, then each person taps **It matches**. A code holds only your name, a random ID, and a public key. Only people you've added can connect to you; anyone else is dropped before a single message is exchanged. **People** lists who you've added, whether they're nearby now or when they last were, and **Remove**.
- **Locked to you two.** Each connection uses the [Noise protocol](https://noiseprotocol.org/noise.html) (`Noise_XX_25519_ChaChaPoly_SHA256`) with the keys from adding each other, so both phones prove who they are and every connection has fresh keys. It's written from the spec on Android's own X25519, ChaCha20-Poly1305, and SHA-256, and checked against the official Noise test vectors. Nearby chats get the green lock, and are stored encrypted on the phone like other internet messages. Your Nearby key is sealed with the Android Keystore and isn't in backups.
- **Waiting and delivery.** A message to someone who isn't around reads **Waiting for Rosa to be nearby** and goes on its own as soon as their phone is seen; it then reads **Sent nearby**, which means their phone confirmed it has it. A message that isn't confirmed is sent again next time, and their phone keeps each message once. Nearby sends words, replies, and reactions as readable text; photos come later.
- **Battery.** Nearby looks for your people while FluidMessages is open. **Stay discoverable** keeps it running when the app is closed, with an ongoing notification, and uses more battery.
- **Can't find each other?** Some Wi-Fi networks stop phones from finding each other. The Nearby page shows this phone's address (such as `192.168.1.20:47610`); type the other phone's address under **Can't find each other?** to connect directly.
- **Channels.** **Join or start a channel** on the Nearby page. An open channel, like **Neighborhood**, is for anyone nearby running FluidMessages: type its name, or tap one under **Open channels nearby**. Its messages are signed with the sender's key (ECDSA P-256), so no phone can change them or write as someone else, but they aren't secret: the chat shows the red lock and says **Anyone nearby can read this channel.** People you've added show by their name; anyone else shows with a short mark after their name ("Maya · 3F9A"), so two people can't pass as each other. Add a passphrase to make a **room**: the name and passphrase make its key (PBKDF2-SHA256), only people who type both can read it or see its name, and it gets the green lock. The passphrase isn't kept; the room's key is sealed on the phone.
- **Passing messages along.** With **Help pass messages along** (on unless you turn it off), your phone keeps channel and room messages and sealed one-to-one messages for others, and hands each to the next FluidMessages phones it meets. Each message is kept once (by its ID), goes at most 8 hops, and is dropped after 7 days; the phone keeps at most 8 MB and takes at most 400 messages from any one phone per connection. A one-to-one message to someone out of range also travels this way, sealed to their key with Noise_X (`Noise_X_25519_ChaChaPoly_SHA256`, written from the spec and checked against the official vectors): carrying phones can't read it or tell who sent it, only a short tag for whom it's for. It still reads **Waiting for Rosa to be nearby** until Rosa's own phone confirms it, and Rosa's phone shows it once however it arrives. While you're in a channel or helping, other FluidMessages phones nearby can see yours by the name you chose; only people you've added can message you one-to-one.
- **Bluetooth.** **Use Bluetooth too** finds phones in Bluetooth range with no Wi-Fi (Bluetooth Classic, without Android's pairing prompt: Noise does the checking). Phones you've met over Bluetooth find each other again on their own; **Let phones find mine over Bluetooth** makes yours visible for 5 minutes, after Android asks, so a new phone can find it.
- **Not yet:** Wi-Fi Direct, photos, and calls. Nearby chats stay on the phone and don't sync to FluidMessages Web, which can't reach the phone's neighbors. If a phone's system lacks the encryption Nearby needs (X25519 and ChaCha20-Poly1305), Nearby says so and stays off.

**Nearby only (no internet)**, on the Nearby page and off by default, makes FluidMessages open no internet connections at all: no chat services, no FluidMessages Web sync or backups, no file-server backups, no link previews, pictures, or GIFs from the web, and no update checks. The inbox says **Nearby only: internet is off in FluidMessages**, with **Turn off**. Texts use the cell network rather than the internet, so **Allow texts over the cell network** stays on unless you turn it off; texts that arrive still show up either way.

### Attachments

Tap **+** in the composer for Photos and videos, Camera, Document, Audio, Location, or Contact. With nothing typed, the microphone records a voice message (AAC, up to 3 minutes). A location is sent as an OpenStreetMap link and appears as a location card that opens your map app. A contact is sent as a vCard. Each protocol carries files in its standard way:

- **SMS** becomes **MMS** for a file, within your carrier’s MMS size limit (often 300 KB–1 MB). Photos are resized to fit, and other files that are too large are refused with the limit shown. Locations stay SMS.
- **Matrix** uploads to your homeserver’s media repository and sends `m.image`, `m.video`, `m.audio`, or `m.file`. Voice messages are marked as voice notes (MSC3245). Received media downloads through authenticated media.
- **Email** sends a normal MIME attachment, up to 25 MB, and receives the first attachment of messages from linked correspondents.
- **XMPP** and **IRC** currently go through Matrix bridges, which deliver files the way each network allows. IRC receives them as links.

Files go to the companion first and are stored in its data volume. Received attachments download according to **Battery and sync**, or when you tap them.

New groups use one protocol that everyone shares. That is MMS for phone numbers. Matrix, XMPP, and IRC groups are set up on the companion for now. If MMS is off, the same text goes to each number separately.

### Money

**+ → Money** requests or sends money through standard payment links, so paying always happens in the other person's own app. It works in two steps: pick how (your usual method sits on top as one big button, then crypto, payment apps and banks, and your own), then fill in only what that method needs. **Monero (XMR)** is the default; the last method you use becomes the new default, and **Settings → Payments** changes it.

- **Crypto:** Monero, Bitcoin, Bitcoin over Lightning (Lightning address or LNURL), USDC and SOL on Solana, USDC and ETH on Ethereum, USDC on Base.
- **Payment apps and banks:** PayPal.me, Venmo, Cash App, Revolut, UPI, and bank transfers by IBAN using the open `payto:` standard. Pick the currency where the service supports several.
- **Your own:** **Add your own…** takes a name and a payment link with `{address}`, `{amount}`, and `{note}` in it, such as `dogecoin:{address}?amount={amount}`. Cards for custom methods show a clear warning, on both sides, because FluidMessages can't check where those links send money.

Google Pay and Apple Pay don't offer payment links that other apps can use, so they aren't listed. FluidMessages never holds money, keys, seed phrases, or card numbers and never signs a transaction. The message is readable text, so people without FluidMessages still see the amount and link. Crypto payments can't be reversed.

FluidMessages Web has the same two-step Money picker under **+ → Money**. There, and for polls, events, and games, each form opens as its own page (the whole screen on a phone-sized window) with **Back** at the top.

FluidMessages Web works on its own, without a phone: it opens with a short welcome on the computer it runs on (no password there), and everything except carrier texts works from it. Its **+** menu groups **Share**, **Create**, and **Fun**. **+ → Effect** can be picked before or after typing: it waits above the message box as a chip (tap to switch, **×** to drop it) and goes with your next message. Photos, GIFs, stickers, and videos each have a **Download** button in the chat and in the full-screen viewer. A new reaction pops up from its bubble. **Settings → Fun and effects** turns message effects, reaction animations, games, dice and random picks, GIFs and stickers, and link previews off for every browser on that server; off, games and dice show as plain text and leave the **+** menu, and reduced motion always stops the animations.

FluidMessages Web also has the phone's photo editor (**+ → Edit a photo**, **Edit** on a photo waiting above the message box, or **Edit** in the full-screen viewer): crop with zoom, rotate, flip, and resize; adjustments; the same filters; drawing; text in eight fonts with the same layouts; other photos and stickers on top; stretching and space around the picture; and **Remove background**, which runs in the browser with the same method as the phone. **+ → Make a sticker** keeps cut-outs in that browser, and they appear under **Your stickers** in the GIF picker. **+ → Voice message**, or the microphone beside **Send** with nothing typed, records up to 3 minutes; voice messages and audio files play in the chat. Photos you attach, paste, or drop wait above the message box with **Edit** and **×**, and are resized for **Settings → Media and GIFs → Photo quality** (saving them again removes location and camera details). The same page turns GIF sites on or off and adds your own. A message's ⋯ menu has the phone's six reactions plus **+** for any emoji, **Select text**, **Share** (where the browser can), **Message details** with earlier versions, and **Delete for me** for internet messages. Right-click or long-press a chat, or open its details, to pin, archive, mute, or block it (blocking there hides the chat in **Blocked**; it doesn't stop delivery), give it a chat code, or pick its wallpaper. **Themes and appearance** adds saved palettes, **Wallpaper** (built-in designs or a photo kept in that browser), **Inbox and toolbar**, bubble tails, and **Motion and sound** (Fluid send and receive sounds made in the browser, haptics on devices that vibrate, and motion, where Off also stops effects). **Settings → Sample chats** opens fictional chats to try everything; nothing is sent. Muted and blocked chats don't chime.

### GIFs, stickers, polls, events, games, and link previews

Every one of these is sent as readable text or an ordinary picture, so people on other apps get something that makes sense, and FluidMessages shows it as a card.

- **GIFs and stickers:** **+ → GIF** or **Sticker**, or insert them straight from your keyboard (Gboard and others). Browse Tenor, GIPHY, Imgur, or Reddit r/gifs right in the picker with no account: open any GIF and tap **Send this GIF** in the bar at the bottom, or long-press a GIF in the results. GIFs too big to send as a link go as a short video. Turn each site off or add your own (with `{query}` where search words go) under **GIF sites to browse** in **Settings → Media, GIFs, and fun**. For search results inside the picker, choose Tenor or GIPHY with your own free API key, and optionally your own compatible API address, in **Settings → Media, GIFs, and fun**. Searched GIFs are sent as a link (light on data, and other apps preview it); GIFs from your phone are sent as a file where the service carries files. **Make a sticker** opens a photo in the editor with the background already being removed, then **Save sticker** keeps the cut-out with a see-through background. Stickers show without a bubble. GIFs and stickers can each be turned off.
- **Polls:** **+ → Poll** with 2 to 10 options. Everyone in the chat taps to vote and sees live counts. People on other apps see a numbered list and can reply with a number, which is counted too.
- **Events:** **+ → Event** shares a title, time (or all day), place, and notes. Everyone can answer **Going**, **Maybe**, or **Can't go** on the card, and it shows the counts and who said what. People on other apps can just reply `yes`, `maybe`, or `no` to the newest invite before it happens. **Add to calendar** saves it straight into a calendar on your phone (Google, CalDAV/DAVx⁵, Exchange, or local; it asks for calendar access once), or opens another calendar app, Google Calendar on the web, or saves an `.ics` file (the open iCalendar standard). It never depends on one calendar app working. `.ics` invites that others send show as the same card.
- **Games:** **+ → Games** offers chess, tic-tac-toe, and four in a row. Pick one, then who goes first (white or black for chess). With FluidMessages, tap the board to play, then **Send**; resign and play again are on the board. Chess has the full rules: castling, en passant, promotion, check, checkmate, and stalemate.
  - **With people on other apps:** they get each move as text with the board drawn in it and a line saying how to answer. They just reply with their move: `e5`, `Nf6`, or `O-O` in chess, a square number in tic-tac-toe, or a column number in four in a row. Their reply counts as their move, and your next move carries it on.
  - **Fair play:** a game message that changes earlier moves, plays for the other side, or keeps going after the game ended is marked as skipped and changes nothing. A number sent after a newer poll counts as a vote, not a move.
  - **On a website instead:** after picking a game, choose where to play. **Lichess** (chess, free, no account) makes a real game link for you: your side opens in your browser and the other link is sent. **Chess.com** (needs free accounts), **Foony**, and **Papergames** (tic-tac-toe and four in a row) open the site; start a private game there and paste its invite link. The chat gets a card with **Join the game**, and other apps get the link.
- **Rock paper scissors:** **+ → Games → Rock paper scissors**. Your pick is sealed (a SHA-256 hash of the game, your pick, and a secret), so you can't change it after seeing theirs. They pick on the card, or reply `rock`, `paper`, or `scissors` from any app. Then tap **Reveal my pick**; FluidMessages checks the reveal against the seal and warns if it doesn't match. Reveal from the device you started on, which keeps the secret. People on other apps can't check the seal themselves, and the message tells them their pick comes first.
- **Dice and random:** **+ → Dice and random** rolls up to six dice (d4 to d100), flips a coin, or picks one of your choices. Your device picks with a secure random generator, and everyone, on any app, sees the same result.
- **Link previews:** the first link in a message shows a card with the page's title, summary, and picture, with a play button for videos (YouTube, Vimeo, Twitch) and the same for songs and articles. Turn previews, or pictures from links, off in **Settings → Media, GIFs, and fun**.

Bubble effects are Slam, Loud, Gentle, and Invisible ink (hidden under sparkles until tapped). Screen effects are Confetti, Balloons, Hearts, and Fireworks. - **Save to phone:** the **Save** button in the full-screen viewer, or touch and hold any photo, video, or file → **Save to phone**, puts a copy in Pictures, Movies, Music, or Downloads, in a FluidMessages folder.

### Voice message transcripts

Under any voice message, tap **Show transcript**. The phone's own on-device speech recognizer writes it out, so the recording never leaves your phone; nothing is sent to a cloud service. Android asks for microphone permission the first time, because its speech recognizer requires it, but nothing is recorded. Transcripts are kept privately in the app's cache. Phones without on-device speech recognition (including most emulators) say so instead. FluidMessages Web doesn't transcribe, because browsers have no private way to do it.

**+ → Contact** shares a contact as a vCard, the standard every phone understands. In FluidMessages it shows as a card with the name, numbers, and emails, plus **Add to contacts** and **Call**. FluidMessages Web shows the same card with **Save contact (.vcf)**.

### Editing photos

Tap **Edit** on a photo waiting to send, **Edit** in the full-screen viewer on any photo in the chat, or **+ → Edit a photo**. The editor has:

- **Adjust:** brightness, contrast, saturation, warmth, tint, and fade.
- **Filters:** Vivid, Mono, Noir, Sepia, Warm, Cool, Fade, Drama, Intense, and Invert. Adjustments apply on top of the filter.

Tap the picture to add words, drag to move, pinch to resize or turn, and double-tap to change the words. Layouts add top and bottom text, a title bar above, a caption bar below, or a label.

## Calls

The bottom tabs are **Phone** on the left and **Messages** on the right. The app reopens to whichever one you used last. **Phone** follows the iPhone Phone app's layout in your current theme:

- **Favorites:** people you've starred.
- **Recents:** calls, with **All** and **Missed** views.
- **Contacts:** a searchable list, with tags for each way you can reach someone (Phone, Matrix, Email, and so on).
- **Keypad:** opens from the round green button on every list, as in Google's Phone app. A typed number that belongs to a contact shows their name.

The sample inbox has its own Phone tab, with made-up contacts and Phone and Matrix calls.

Tap someone's photo or ⓘ to open their page. It shows their phone numbers and accounts, every chat with them and its latest message, and recent calls. It also has a star to add them to Favorites, and **Message**, **Call**, and **Video** buttons (video only for Matrix). Conversation details have the same buttons. When there's more than one way to do something, the button asks which one and can remember your choice; hold the button to choose again. Phone-network calls go through Android's call screen. A Matrix chat's details also offer **Voice call** and **Video call**.

Matrix calls appear in Recents next to phone calls, and **Settings → Accounts and calls → Calls → Show regular phone calls** can leave Android's phone calls out. **Meeting links**, turned on in the same page, call anyone on any service. You pick the service each time: Zoom (first, and the default), Google Meet, Microsoft Teams, and Jitsi Meet, all on at first, plus services you add yourself in **Calls → Meeting links → Your own services** (a name and your https link). FluidMessages has no account with Zoom, Google, or Microsoft, so for those it sends your own meeting link, which you save once. Jitsi Meet is free and open source, makes a new room each time with no account, and can use your own server. These calls show a yellow lock, because the meeting service can see who joins and may record. The call screen uses the chat's wallpaper and shows the call's lock status at the top. In the sample inbox, calls open the same screen as a pretend call. The keypad switches between **Number** and **Username**, so you can call a Matrix ID directly. **Settings → Accounts and calls → Calls** has a switch for each way of calling (Phone, Matrix, XMPP, SIP, and meeting links), separate from messaging. For example, Matrix can be off for messages but on for calls.

- **XMPP calls** use Jingle (XEP-0166/0167, with call ringing from XEP-0353), the same as Conversations and Dino. They need XMPP connected from this phone, and are end-to-end encrypted with DTLS-SRTP.
- **SIP calls** use [JsSIP](https://jssip.net) (MIT, about 234 KB) over a secure WebSocket. Add the account details from your SIP provider, which must accept `wss://` connections. SIP can also call regular phone numbers through your provider. These calls show a yellow lock, because the provider can access them. **Receive SIP calls** controls when the phone stays signed in to your provider so SIP calls can ring it: **Off**, **While FluidMessages is open**, or **Always**. Always shows Android's ongoing notification and uses a little more battery. One SIP call rings at a time; other callers hear busy.
- **Meeting links** are on by default. When you start one, you choose which chat gets the link (any way you can message that person), copy it instead, or don't send it. In FluidMessages, on the phone and the web, the link shows as a call card with a **Join** button. Other apps see a plain link ("📹 Join my video call: https://…").
- **During a call** you get mute, speaker, camera on/off and flip, a keypad for touch tones (it replaces the other buttons, and **Hide** brings them back) and hold (SIP), and **Record** on Matrix, XMPP, and SIP calls. The screen also shows a timer and the call's lock status, over the chat's wallpaper. Recordings save to your phone's Recordings folder (voice) or Movies folder (video), under FluidMessages, only inside the app, or any folder you pick, including an SD card or a folder a storage app offers. Choose separately for voice and video calls in **Settings → Calls → Call recording**, which can also send "I started recording this call" in the chat. Android doesn't let apps record regular phone calls.

Internet calls use WebRTC, with Matrix VoIP (version 1) events for signaling, so the other person can answer in FluidMessages, Element Web or desktop, or another Matrix app that supports one-to-one calls. Media goes directly between devices. The homeserver's TURN relay is used when both sides are behind strict networks. Chats linked on the phone ring while FluidMessages is open, or when background sync runs. Companion-linked chats ring while the app is open. FluidMessages doesn't replace the default phone app, and SIP and XMPP calls aren't supported yet.

## Privacy and security

**Inbox filters.** The filter menu at the upper trailing edge of the inbox has **Inbox**, **Unread**, **Favorites** (one-to-one chats with people starred in the Phone tab, or Calls on FluidMessages Web), **Groups** (group texts, channels, and rooms), **Direct messages**, one filter per service you use (**Texts**, **Matrix**, **XMPP**, **Email**, **IRC**), **Archived**, and **Blocked**, and the inbox title follows the choice. **Settings → Messaging → Inbox filters** shows or hides each one and moves it up or down; Inbox is always there, and the choice is shared with FluidMessages Web. Inside the open private folder the menu's **In the private folder** filters apply to its chats only, and the folder never shows in the other filters. In decoy mode they apply to the decoy chats, and Favorites stays empty. The sample inbox filters its own sample chats and favorites.

**Settings → Privacy and security**:

- **App lock** asks for your fingerprint, face, or screen lock and keeps FluidMessages out of screenshots and recents.
- **Stored messages are encrypted.** Internet and picture messages, saved accounts, and the pairing token are sealed with AES-256-GCM. The key is wrapped by Android Keystore.
- **Private folder** moves conversations, or whole services, out of the inbox into the **Private folder**. Every inbox's filter menu lists Private folder, set up or not. A wrong passcode opens an empty folder, so nobody can tell whether anything is hidden. Open it with your fingerprint or screen lock when that's on, or type the passcode into search. Switching to another folder asks for the passcode again before it closes (you can turn that off in its settings), and it always closes when you leave the app. Texts in the private folder move out of Android's shared SMS store into an encrypted vault, which uses an EC P-256 public key, so new texts are stored while it's closed. Their alerts name no one. They never sync to FluidMessages Web, which also hides its own copies. You can leave the section out of Settings, so it only appears after you enter the passcode. A forgotten passcode can't be recovered.
- **Emergency erase passcode** is a second passcode. Typed instead of your real one (in search, Private folder, or a chat lock), it erases everything in FluidMessages at once.
- **Decoy mode** is for when someone else is using your phone. It swaps the inbox, the Phone tab, and the contacts you can message for pretend chats plus only the real people you allow. Turn it on from the inbox filter menu, the app icon's **Quick hide** shortcut, or the **Quick hide** tile in your phone's quick settings, which works even outside the app. To end it, long-press the **Messages** title, tap the tile again, or type your private folder passcode into search; each asks for the passcode. Pretend chats are never sent.
- **Chat locks.** The **Chat lock** switch in a chat's details hides its previews and asks before the chat opens. By default it asks for your phone's own PIN, pattern, fingerprint, or face; turn off **Use your phone's screen lock** to use a separate passcode instead. A locked chat locks again as soon as you go back to the inbox or open another chat, and whenever you leave the app. **Settings → Privacy and security → Chat locks** does the same for every chat of one kind. On FluidMessages Web the lock can use the computer's screen lock (Windows Hello, Touch ID, or the device PIN) where the browser allows it, or a code.
- **FluidMessages encryption** works when both people use FluidMessages and enter the same key, made in the app or agreed in person. Turn it on by default for each protocol: SMS, MMS, Matrix, XMPP, Email, or IRC. A chat's own choice in its **Security** section always overrides the default. Keys are hidden until you tap the eye, and can be copied. Messages sent from the browser companion aren't encrypted this way; the companion says so in those chats. Other apps and the carrier see `FM1:` followed by Base64 of a key id, a nonce, and AES-256-GCM ciphertext. The key is PBKDF2-HMAC-SHA256 with 100,000 rounds and the salt `FluidMessages SMS 1`. Encrypted texts are limited to 1,000 characters.
- **Disappearing messages** remove messages after a timer you set, from 30 seconds to a year, per chat or for every chat. Messages sent or received after the timer is set are removed on the phone, on time even when FluidMessages is closed or the phone restarted, and on the companion at its next sync. SMS, MMS, Email, and IRC can't remove the other person's copy. Your own Matrix messages are redacted, and your own XMPP messages are retracted (XEP-0424). Encrypted texts, Matrix messages, and XMPP messages carry the timer, so FluidMessages on the other side removes them too. Other apps keep their copies.

Each chat's header and **Security** section show a colored lock:

- **Green:** end-to-end or FluidMessages encryption.
- **Yellow:** encrypted in transit only.
- **Red, unlocked:** not encrypted.

A chat's details group encryption, disappearing messages, hiding, and its chat code under **Security**. Rows that only give information show an ⓘ instead of an arrow.

**Settings → Reset** has two options:

- **Reset settings to defaults** keeps your messages, accounts, companion, the private folder, codes, and keys.
- **Erase everything** removes all of FluidMessages' data from the phone. Texts in Android's message store stay.

The companion's settings have their own reset.

### Tor

**Settings → Privacy and security → Connect through Tor** is off by default. Tor hides your internet address from chat servers and from anyone watching your network. It makes connections slower and less reliable, and some servers block Tor. Texts (SMS) and calls over your phone plan never use Tor. Turning it on shows this warning in place, and **Turn on** waits until you switch on **I understand**.

- **On the phone, Tor runs in Orbot.** FluidMessages doesn't include Tor itself. Install Orbot from F-Droid or the Guardian Project, open it, and tap **Start**. The setting shows **Connecting to Tor…**, **Connected through Tor**, or **Tor isn't running**, and a phone connection's **Connection** section in chat details shows the same.
- **Through Tor:** Matrix, XMPP, IRC, and email connected from the phone, FluidMessages Web when it's on the internet, link previews, pictures from links, GIF search, Lichess games, update checks, and SFTP and WebDAV backups. Server names go to Tor without being looked up on the phone, so DNS doesn't leak. Email goes through Orbot's HTTP port (8118), and everything else through its SOCKS port (9050).
- **Never around Tor:** while Tor is on but not running, connections wait and say why. Nothing quietly connects without Tor.
- **Connects directly:** FluidMessages Web and file servers on your home network (192.168.x.x, `.local`, Tailscale), which Tor can't reach and which stay on your network.
- **Off while Tor is on:** FTP backups to the internet, and GIF sites, which open in a web page that can't use Tor.
- **Calls:** Matrix, XMPP, and SIP calls can't go through Tor, so they're off while Tor is on. **Allow calls without Tor** turns them back on, and then they connect directly, so the other person and the call server can see your internet address.
- **IRC:** many networks, like Libera.Chat, only let Tor in for a registered nickname signed in with SASL, and some block Tor. When a network refuses, the server chat says so in plain words.

FluidMessages Web has its own **Connect through Tor** setting for the connections the server makes (see [self-hosting](self-hosting.md#tor)).

### Group members

A group's details can **Add people** or **Remove someone**:

- **Matrix:** invite and kick. Removing someone needs permission in the room.
- **XMPP:** invite an address, or kick a nickname as a moderator.
- **IRC:** `INVITE` and `KICK`, which may need operator status.
- **Group texts:** carriers treat every set of people as its own group, so adding or removing someone starts a new group text.

## Read-only mode

Turn off every chat service in **Settings → Chat services** and FluidMessages becomes read-only: you can still read every chat, but the compose button is gone, nothing can be sent, and the inbox says why. Turn off every way to call in **Settings → Calls** and the Phone tab still shows your calls and contacts, but the keypad and call buttons go away and no call can be placed. Incoming messages and calls still arrive. Either one can be on without the other.

## Backups

Open **Settings → Backups**. It has three groups: **On this phone** (export, share, restore, or schedule a folder), **Your own server** (SFTP, WebDAV, FTPS, or FTP), and **Cloud services** (OneDrive, Google Drive, S3). Select one or more categories in each backup or schedule: SMS, global theme and layout, sounds and effects, per-chat themes, conversation settings, wallpaper photos, and MMS, internet messages, and protocol settings. That last category embeds attachments up to 2 MB each (24 MB in all) and never includes account passwords. The wallpaper photo category embeds images for a restore on another device. Message attachments and group chats require MMS or RCS support. Backups combine the selected categories in one compact archive. Encryption is enabled by default and uses AES-256-GCM with a salted PBKDF2-HMAC-SHA256 key. Restore previews the archive and merges SMS into the Android provider with duplicate checking. Local and cloud schedules are independent, use a 15-minute to 7-day interval set with separate Hours and Minutes fields, and run when Android allows background work. To update a local schedule’s contents or interval, open **Local folder schedule**. The current folder stays selected, and an existing password can be kept. Scheduled archive passwords are stored using Android Keystore.

### Back up through an Android storage app

### Your own file server

Choose **Add a file server** to back up straight from the phone to a server you control, with nothing in between. Pick the type, then enter the address, port, username, password, and folder:

- **SFTP** (port 22): any server you can reach over SSH, including most NAS boxes and hosting accounts. The first connection remembers the server's key; if it ever changes, backups stop with a warning, the way SSH does.
- **WebDAV** (port 443, HTTPS only): Nextcloud, ownCloud, Synology, QNAP, and similar. For Nextcloud, use an address like `cloud.example.com/remote.php/dav/files/you`.
- **FTPS** (port 21): FTP with explicit TLS.
- **FTP** (port 21): not encrypted in transit, so use it only on your own network, with an encrypted backup.

Every port can be changed. **Save** tests the connection first; **Test connection** only checks it. The folder is created if it's missing. Each server has **Back up now**, its own **Backup schedule**, and **Restore newest backup**, which downloads the most recent `.fmb` archive and shows what's in it before restoring. Server passwords and scheduled archive passwords are stored encrypted with Android Keystore and are never included in backups.

**Backup file name** in Backups defaults to a date-stamped filename. A fixed filename replaces the same archive in scheduled folders and companion cloud destinations. For manual exports and sharing, Android and the chosen storage app handle existing files. Update the companion alongside Android to use fixed cloud filenames.

**Export a file** and **Restore from a file** open Android's file picker. You can use a cloud app that makes its files available through the picker. **Share to a storage app** hands an archive to an app you select in the share menu. **Local folder schedule** also works with a storage app that offers a writable folder via the picker. These options work without pairing a companion. [Android storage access documentation](https://developer.android.com/training/data-storage/shared/documents-files)

### Phone or companion per cloud destination

Open a provider in **Settings → Backups**, then choose **Phone** or **Companion** in **Backup method**. Phone lets you save or restore through Android’s file picker, hand off a backup to a storage app, or schedule backups to a writable folder. Select a cloud folder if the provider exposes one, or choose a device folder synced by a storage app. Provider credentials and sync for this route are handled by the selected Android app. Phone and companion schedules are separate and stay configured when you switch the selector.

### OneDrive, Google Drive, and S3 through the companion

Cloud destinations use your paired HTTPS companion. The companion runs rclone and stores the provider credentials in its private data volume. Configure each provider you want from your companion host:

```sh
docker compose up -d --build
docker compose exec fluidmessages rclone config
```

Create rclone remotes for [OneDrive](https://rclone.org/onedrive/), [Google Drive](https://rclone.org/drive/), and [S3](https://rclone.org/s3/) as needed. Enter the remote names and backup locations in your Compose environment. For example:

```dotenv
FLUID_BACKUP_ONEDRIVE=onedrive:FluidMessages
FLUID_BACKUP_DRIVE=drive:FluidMessages
FLUID_BACKUP_S3=s3:your-bucket/FluidMessages
```

Run `docker compose up -d` again. If you use a reverse proxy, allow roughly 65 MiB request bodies and 200-second upstream reads for backup transfers. On Android, open **Settings → Backups** and choose a provider. **Back up now** lets you select categories and upload a one-time backup with no schedule. **Backup schedule** sets a recurring interval and categories for that provider, and **Run saved schedule now** uses those saved settings. Cloud schedules are tied to the paired companion address. Update them explicitly after changing servers. **Back up all cloud schedules** runs the configured phone folder and companion schedules. **Restore newest backup** finds and downloads the most recent FluidMessages archive for that provider and asks for confirmation before importing it. Re-pair a new phone with the same HTTPS companion and enter the archive password to restore there.


FluidMessages downloads MMS, including group MMS, over mobile data. Replies in a group join the group you started. Android often doesn't know the phone's own number, so FluidMessages learns it from the first group or picture message addressed to you, or reads it when you allow phone number access. Group messages that arrived before that move into the right group once it's learned.
